# План на пять дней

Составлен 25 ноября после разбора проекта с семи сторон: данные, качество, эксплуатация, код,
интерфейс, рынок и взгляд жюри. Ниже — как устроен сервис, что чиним, что запускаем, кто за ним
следит и как мы это показываем.

## Как всё устроено

```
 источники            страницы приёмных комиссий, приказ с перечнем РСОШ, исходный XLSX
     │
 обход                just refresh-sources: находит PDF, xlsx, HTML; хранит хэш и дату
     │
 извлечение           документ → записи в нашем JSON (формат ниже); у каждой записи цитата и страница
     │
 проверка кодом       цитата есть на странице, поля по схеме, олимпиада есть в справочнике
     │
 приёмка              человек смотрит diff с текущими данными и принимает файл в репозиторий
     │
 сборка базы          XLSX + принятые JSON + справочники → PostgreSQL
     │
 выдача               API → сайт, мини-приложение MAX, бот, помощник
     │
 школьник ──► жалоба «не совпадает с документом» ─┐
 сверщик  ──► «противоречит документу» ───────────┤
                                                   ▼
                          очередь оператора → правка → снова сборка
```

Каждый шаг меряем отдельно:

| Шаг | Чем меряем |
|---|---|
| извлечение | эталон «документ → JSON» по 10 документам |
| база | эталон из 80 строк, сверенных с документами |
| выдача | 30–40 сценариев «дипломы → что должно и не должно быть» |
| помощник | набор из 60–80 вопросов с ожидаемыми фактами |
| жизнь сервиса | жалобы: сколько пришло, сколько подтвердилось, за сколько исправили |

## Что запускаем для школьника

1. **Кампания 2027.** Дипломы 2024–2027 годов принимаются. У олимпиад, которых нет в перечне
   2026/27, стоит пометка. Переключатель «по проекту правил 2027» показывает, что изменится
   (например, призёру — 100 баллов вместо БВИ), со ссылкой на документ.
2. **Честная выдача.** В форме диплома ВсОШ можно выбрать этап. Строки без «кому» помечены
   «проверить». В итоге написано, по скольким вузам у нас нет данных. Бейджи считают
   направления, а не строки таблицы.
3. **«Что добрать на ЕГЭ».** Одной фразой: «информатика 72, нужно 75 — откроется ещё 38
   направлений».
4. **«Хочу в вуз — какие олимпиады писать».** Для 8–10 классов. Выбираешь до трёх направлений
   и получаешь список олимпиад с профилем, уровнем и порогом ЕГЭ по правилам 2027.
5. **Поиск олимпиад.** «нто ии» находит НТО с профилем «Искусственный интеллект»; мусорные
   профили убираем; карточки олимпиад показываем на сайте, а не только в помощнике.
6. **Новые вузы.** Добираем 3–6 пустых по их документам: РАНХиГС, МАИ, МЭИ, Сеченова, СПбГУ.
7. **«Не совпадает с документом».** Кнопка у каждой строки льготы (подробнее — в разделе
   «Жалобы»).
8. **Помощник.** Включаем снова, если пройдёт порог качества.
9. **Бот MAX.** Подписка «напиши, когда вузы опубликуют правила 2027», ответ на жалобу,
   «Поделиться» в чат класса.
10. **Свои данные.** Кнопка «Удалить мои данные». В логах больше нет дипломов и IP.

## Извлечение из документов в наш JSON

Главный вопрос к данным — насколько точно мы переносим документ вуза в свои записи. Сейчас
извлечение идёт через XLSX, собранный когда-то полуручным способом, и как его ни проверяй,
повторить сборку нельзя. Дальше переходим на прямой разбор документов в единый формат
и меряем его на эталоне.

### Формат записи

Одна запись — одна льгота: вуз, направление, олимпиада с профилем, тип льготы и условия.

```json
{
  "university": "НИУ ВШЭ",
  "campaign": 2027,
  "program_code": "01.03.02",
  "program_name": "Прикладная математика и информатика",
  "benefit_type": "bvi",
  "olympiad": "Высшая проба",
  "profile": "математика",
  "levels": [1],
  "winner_role": "winner",
  "grades": [10, 11],
  "ege": {"subjects": ["math"], "min": 75},
  "source": {"url": "https://…/olymp_2027.pdf", "sha256": "…", "page": 12, "quote": "…"}
}
```

- `benefit_type`: `bvi`, `100`, `extra_points`.
- `winner_role`: `winner`, `prizewinner`, `both`; `null`, если в документе не сказано. Пустое
  значение лучше догадки, на сайте такая строка получит пометку «проверить».
- Поля совпадают с колонками таблицы `benefits`, поэтому сборка берёт файл как есть.
- Файлы лежат в `data/extracted/<вуз>-<кампания>.json`, рядом — хэш документа и версия
  извлекателя.

### Эталон

- **Документы.** 10 документов разного вида:
  - большая таблица в PDF — ВШЭ;
  - сплошной текст — ИТМО;
  - соотнесение профилей — МГУ;
  - правила «любая олимпиада по профилю» — УрФУ;
  - группы направлений — Бауманка;
  - xlsx — РАНХиГС;
  - HTML-страница;
  - два документа пустых сейчас вузов — МАИ, МЭИ.

  Из длинных документов берём 2–3 страницы, а не весь файл.
- **Разметка.** Со страницы документа записываются все льготы в формате выше, только по самому
  документу, без оглядки на нашу базу: иначе мы мерили бы базу ей же. У каждой записи цитата,
  и код проверяет, что она есть на указанной странице.
- **Где лежит.** `data/eval/extraction/<документ>.json` вместе с адресом и хэшем документа.

### Метрики

Запуск — `just eval-extract`, результат — таблица по документам и по способам извлечения:
код по таблицам, код с моделью и старый XLSX для сравнения.

| Метрика | Что значит |
|---|---|
| точность записей | доля извлечённых записей, которые есть в эталоне |
| полнота записей | доля записей эталона, которые мы извлекли |
| точность полей | у совпавших записей отдельно: `winner_role`, `levels`, `grades`, `ege.min`, `ege.subjects` |
| цитаты | доля записей, чья цитата найдена на указанной странице (проверяет код) |
| пустые поля | сколько полей честно оставлено пустыми — это не ошибка, но считаем |
| цена и время | на один документ |

Запись совпала, если совпали вуз, код направления, олимпиада, профиль и тип льготы.

Порог, чтобы разбирать вуз автоматически: ни одной лишней записи с неверным «кому» или типом
льготы, точность записей не ниже 95%, полнота не ниже 90%. Ниже порога вуз разбираем, но
каждую запись человек смотрит руками.

## Жалобы на несоответствие

Сейчас есть только общее «Нашли ошибку» с текстом, и его никто не читает. Делаем так:

- **Где.** Кнопка «Не совпадает с документом» у каждой строки льготы, общее «Нашли ошибку»
  на карточке остаётся.
- **Что выбирает пользователь.** Причину:
  - льготы нет в документе;
  - другой тип (БВИ или 100 баллов);
  - только для победителей;
  - другой класс или уровень;
  - другой порог ЕГЭ;
  - ссылка не открывается;
  - другое.

  Дальше по желанию комментарий и ссылка на документ. Ключ строки и то, что было на экране,
  прикладываются сами.
- **Кто ещё пишет в очередь.** Сверщик, когда строка противоречит документу. Мониторинг, когда
  поиск часто пустой. У записи есть источник: пользователь, сверщик или мониторинг.
- **Статусы.** Новая → проверяем → исправлено / данные верны / дубль. Решение «данные верны»
  сопровождается цитатой из документа.
- **Что делает оператор.** Получает уведомление в боте, сверяет с документом. Если ошибка
  подтвердилась — правит разбор или справочник с тестом и пушит.
- **Что видит пользователь.** Если жалоба отправлена из MAX, бот пишет ответ. У исправленной
  строки на сайте пометка «исправлено 26.11 по сообщению пользователя».
- **Что остаётся нам.** Каждая подтверждённая жалоба превращается в сценарий регрессии
  и больше не повторится. В `/stats` видно, сколько жалоб пришло, сколько подтвердилось
  и за сколько часов исправили.
- **Защита.** Лимит на посетителя, длина текста, предупреждение «не пишите личные данные».
  Выгрузка в CSV экранирует формулы.

## Оператор

Оператор — дежурный из команды. Через него проходит всё, что требует решения человека:
жалобы, новые документы вузов, состояние сервиса.

| Когда | Что | Чем |
|---|---|---|
| Каждый день, 10 минут | Смотрит сводку: новые жалобы, частые пустые поиски, ошибки, расход запросов к модели | сообщение бота в MAX |
| По жалобе | Сверяет строку с документом, ставит статус. Если ошибка — правка и пуш | `/reports` |
| Раз в неделю | Обход сайтов вузов. Документ изменился — разбор, diff, приёмка | `just refresh-sources`, `just data-diff` |
| Новый вуз или ссылка | Страница вуза в реестр, разбор, проверка JSON, коммит | `university_pages.py`, `data/extracted/` |
| Раз в сезон | Новый перечень РСОШ, новая кампания: год в настройке, пересборка, сверка diff | настройка кампании, `just data-diff` |

### Почему не админка над базой

База каждый раз собирается заново. Правка, сделанная прямо в базе, пропадёт при следующей
выкатке. Поэтому вся правда лежит в файлах репозитория:

- `university_pages.py` — где у вуза документы;
- `data/university_documents.json` — найденные файлы;
- `data/extracted/` — принятые записи по вузам.

Любую правку видно в git, и пересборка её не теряет.

Бот-оператор в MAX отвечает только тем, кто в белом списке:

- присылает уведомление о новой жалобе и утреннюю сводку;
- `/reports` — открытые жалобы, у каждой кнопки статусов;
- `/stats` — поиски, пустые выдачи, жалобы, «Поделиться», бюджет модели за сутки;
- `/health` — живы ли API, база, помощник; версия данных.

Если останется время — страница `/ops` только для чтения: очередь с цитатой из документа
рядом со строкой.

### Как добавить вуз

1. Добавить в `university_pages.py` адрес раздела с документами.
2. `just refresh-sources --only <вуз>` найдёт PDF и таблицы.
3. Извлечение в `data/extracted/<вуз>-2027.json`. Таблицы разбирает код, модель только
   сопоставляет названия олимпиад со справочником. Цитаты проверяет код.
4. Посмотреть файл (около часа на вуз) и поправить.
5. `just data-diff` покажет, что изменится в выдаче. Коммит, пуш.

## Качество помощника

- **Набор вопросов.** Готов: 69 вопросов (`backend/api/tests/assistant_questions.jsonl`) — школьник,
  родитель, «стоит ли ехать на НТО», «куда без экзаменов с призёром Высшей пробы», вузы без
  данных (МФТИ), олимпиады не из перечня. Ожидания (какие факты должны быть, чего быть не
  должно) выводит из собранной базы `just assistant-cases` в `assistant_cases.jsonl`; после
  пересборки базы команда запускается снова. Проверок «в ответе есть слово» нет.
- **Метрики:**
  - доля ответов с фактической ошибкой — отдельно до фактчекера (сырой ответ модели) и после;
  - доля «в базе нет данных» там, где данные есть;
  - доля выдумок там, где данных нет;
  - время ответа, медиана и p95;
  - цена ответа.
- **Фактчекер.** Самые дорогие ошибки ловит `claims.py` по строкам базы: «победителям и
  призёрам» вместо «только победителям» (и наоборот), «100 баллов» вместо БВИ, порог не по тому
  предмету или не то число, олимпиада вне перечня вуза.
- **Провайдеры.** Один набор на 2–3 моделях, в том числе на российской (GigaChat или
  YandexGPT). Выбирает команда: важны и качество, и то, где хранятся вопросы школьников
  (152-ФЗ).
- **Порог включения:** ни одной ошибки «кому» и «тип льготы» на наборе, остальных ошибок
  не больше 5%, p95 меньше 20 секунд. Не прошли к третьему дню — на защите показываем запись.
- **Бюджет.** 45 запросов к модели в сутки — это 15–20 сообщений на весь сервис. Поднимаем под
  выбранного провайдера и показываем расход в `/stats`.
- **Где запускается.** Вручную или ночью, не в CI: `just assistant-eval --provider имя --out
  отчёт.json`. Профили провайдеров — в `OLYMP_LLM_PROFILES` (JSON: адрес, ключ, модель, цена
  за миллион токенов), `--provider stub` проверяет цепочку без LLM-API. В отчёте: дата,
  провайдер, модель, версия промпта, метрики, порог включения.

## Качество данных и выдачи

- **Эталон строк.** 80 строк базы, выбранных по группам: большие таблицы, строки «по
  профилю», строки без «кому», ИТМО, ВсОШ. Плюс 15 фрагментов документов — чтобы ловить
  пропущенные льготы. По нему же меряем сверщик: пометку «сверено» на
  сайте включаем, только если ложных «подтверждено» ноль.
- **Стабильный ключ строки.** Сейчас у строки только порядковый номер сборки, и он меняется
  при любой правке. На ключе «вуз + направление + олимпиада + профиль + тип» держатся
  жалобы, сверка, эталон и сравнение 2026 с 2027.
- **`just data-diff` в CI.** На каждый пуш показывает, какие строки появились, пропали или
  изменились. Вместо 14 итоговых чисел в тесте сборки.
- **Сценарии.** 30–40 наборов «дипломы → что должно быть в выдаче и чего быть не должно».
  Запрещённых совпадений ноль, запускаются в CI.
- **E2E.** Пять сценариев в Playwright на телефонной ширине.

| 4 | пустые вузы — тем извлечением, что прошло порог | метрики эталона строк, сверщик, сценарии в CI | поиск НТО, карточки олимпиад | `/ops` если успеваем, презентация |
| 5 | только исправления | e2e | только исправления | прогоны демо, запись на запас |

Если не успеваем, отказываемся в таком порядке: `/ops`, вузы сверх трёх, подписка в боте.
Кампанию 2027, честную выдачу, жалобы и измеренную точность не режем.

За два дня до защиты в `main` идут только исправления.

## Как преподносим

Рассказ строим вокруг доверия, а не вокруг технологий.

1. **Проблема, 30 секунд.** Правила льгот разбросаны по сотням страниц PDF у каждого вуза
   и меняются каждый год. В 2027 меняются сильнее обычного. Школьник с дипломом не знает,
   что он ему даёт, и узнаёт об этом слишком поздно.
2. **Демо, 90 секунд.** Школьница открывает «Олимп» в MAX и вводит два диплома. Видит вузы
   и направления, условия, сколько добрать на ЕГЭ. Переключает «по правилам 2027» — часть БВИ
   превращается в 100 баллов. Делится результатом в чат класса.
3. **Почему верить, 60 секунд.** Показываем путь одной строки: документ вуза → запись
   с цитатой и страницей → проверка кодом → человек принял → сайт. Две цифры на эталонах:
   точность извлечения и точность базы. Честно говорим, чего у нас нет: «по МФТИ данных нет».
4. **Сервис живой, 30 секунд.** Жалоба «не совпадает» → уведомление дежурному → исправление
   → ответ в MAX. Сколько жалоб пришло и за сколько часов закрыли.
5. **Дальше, 15 секунд.** Все вузы из перечня; напоминания о регистрации на олимпиады;
   режим для учителя.

ИИ в рассказе — инструмент внутри конвейера: находит, где в документе льгота, и сопоставляет
названия. Решает код и человек. Помощник показываем, только если он прошёл порог.

## Что получаем в итоге

Отметки: сделано / не сделано.

- Сделано. Школьник 2027 года вводит диплом и видит льготы по перечню 2026/27, с пометкой, что
  изменится по новым правилам. Ложных БВИ за региональный этап нет.
- Частично. Эталон извлечения и метрики есть (`just eval-extract`); эталон базы на 80 строках не готов.
- Не сделано. Данные новых вузов из их документов в общем формате: файлы извлечены, в сборку не входят.
- Сделано. У каждой строки есть кнопка жалобы; жалоба доходит до дежурного в боте; исправленная
  жалоба становится регрессией.
- Не сделано. Помощник либо прошёл порог, либо честно выключен; сравнение моделей.
- Частично. Правка разбора показывает diff выдачи (`just data-diff`, CI). Сценарии «дипломы → выдача»
  в CI и e2e не заведены.
- Не сделано. Проверка, что выкатка идёт на сервер, который отдаёт домен; проверенный бэкап.
- Не сделано. Демо на 3 и 5 минут и запись на случай сбоя сети.
