# F-01. «Поделиться» и стабильные ссылки

- Приоритет: P0
- Статус: сделано (T-010…T-013)
- Дата: 2026-11-07
- Требования продукта: FR-22, FR-23

## Зачем
Школьник показывает результат другу, родителю или учителю, а учитель отправляет выдачу в
беседу класса. Для MAX это главный вирусный механизм: каждое «Поделиться» приводит нового
пользователя в мини-приложение. Открытие экранов по `startapp` уже было, но не было кнопки и
отправки, а ссылки с id ломаются после пересборки базы (ADR 0007).

## Пользовательские истории
- Как школьник, я хочу отправить другу карточку направления, чтобы он увидел те же олимпиады.
- Как школьник, я хочу поделиться итогами своих дипломов с учителем или родителем.
- Как учитель, я хочу отправить в беседу класса выдачу по олимпиаде («вот куда даёт НТО по ИИ»).
- Как получатель, я открываю ссылку и сразу вижу тот же экран — в MAX или в браузере.

## Что можно расшарить

| Объект | Где кнопка | Что увидит получатель |
|---|---|---|
| Карточка направления | шапка `ProgramView`, справа от вуза | вуз, направление, таблицы льгот с фильтром по типу льготы отправителя |
| Выдача по олимпиаде | шапка карточки олимпиады (`OlympiadHead`) — и в списке вузов, и на экране вуза | олимпиада, профиль, список вузов или льготы выбранного вуза |
| Итоги дипломов | «Поделиться итогами» во всю ширину под итоговой карточкой `DiplomasView` | **только просмотр**: дипломы отправителя и их итоги, без правки и удаления; кнопка «Проверить свои дипломы» возвращает к своим |

## Поведение

**Кнопка.** Иконка «поделиться» + подпись «Поделиться»: компактная пилюля в шапке карточки (в пару
к «← Все вузы»), у итогов дипломов — вторичная кнопка во всю ширину.

**Ссылка готовится заранее.** MAX и браузеры открывают меню «поделиться» только сразу в ответ на
нажатие (у `shareMaxContent`: «если клика не было, экран шеринга не откроется»), а запрос к API —
это задержка. Поэтому `ShareButton` создаёт ссылку, когда экран показан (`POST` идемпотентен:
тот же экран — та же ссылка), и по нажатию сразу открывает меню. Скрытая вкладка ссылок не
создаёт. Если ссылка не успела создаться, нажатие создаёт её («Готовим ссылку…»).

**Отправка:**
1. В MAX: `WebApp.shareMaxContent({ text, link })` → выбор чата; ссылка — на мини-приложение.
   Ответ `cancelled` — без сообщений. Метод не сработал — `shareContent` (меню телефона).
2. В браузере: `navigator.share({ title, text, url })`, иначе копирование в буфер и тост
   «Ссылка скопирована».
3. Тактильный отклик `success` после отправки (на телефоне в MAX).
4. Ответа меню кнопка не ждёт: меню модальное, а клиент MAX может и не ответить.

**Текст сообщения** (до 200 символов, без персональных данных, длинное название обрезается):
- направление: «НИУ ВШЭ · Прикладная математика и информатика: БВИ дают 54 олимпиады. Смотри в «Олимпе»»
- олимпиада: ««Высшая проба» (математика): БВИ в 23 вузах, 100 баллов — в 31. Смотри в «Олимпе»»
- олимпиада в вузе: ««Высшая проба» в УрФУ: льготы на 96 направлений. Смотри в «Олимпе»»
- дипломы: «Мои дипломы дают БВИ в 12 вузах и 100 баллов в 18. А твои?»

Единицы — вузы и олимпиады, а не строки таблиц.

**Ссылки.** Две формы одного токена:
- MAX: `https://max.ru/<бот>?startapp=s_<token>`
- браузер: `https://<сайт>/s/<token>` → страница открывает приложение на нужном экране.
Если бот не настроен (`/v1/max/config` → `enabled: false`), используется только браузерная ссылка.

**Открытие.** `OlympApp` при `start_param` вида `s_<token>` (`parseStartParam`) или на странице
`/s/<token>` запрашивает снимок и открывает экран с фильтром отправителя. Нет токена, ссылка
устарела или объекта больше нет — тост «Ссылка устарела — открыли главный экран». Онбординг по
ссылке не показывается. Старые `startapp=program-<id>` / `olympiad-<id>` / `diplomas` работают.

## Данные и API

Снимок хранит **стабильные ключи** (не id), чтобы ссылка жила после пересборки базы.

```
share_links(
  token         text primary key,    -- 10 символов base62 из secrets
  kind          text not null,       -- 'program' | 'olympiad' | 'diplomas'
  payload       jsonb not null,      -- см. ниже
  payload_hash  text not null unique, -- sha256 канонического JSON (kind + payload)
  created_at    timestamptz default now(),
  expires_at    timestamptz not null, -- 90 дней с последнего «Поделиться» этого экрана
  opened_count  integer default 0,
  last_opened   timestamptz
)
```

| kind | payload |
|---|---|
| `program` | `{program: "<вуз>\|<направление>\|<профиль>\|<коды>", benefit_type}` |
| `olympiad` | `{olympiad: <squash_key>, profile: <squash_key>?, university: <squash названия вуза>?, benefit_type}` |
| `diplomas` | `{diplomas: [{spec, olympiad, profile}], benefit_type}` (≤ 20; названия — из базы) |

**Ключ направления** — `olymp_domain.program_key.program_stable_key`: squash названия вуза
(оно уникально), squash направления без кодов, squash профиля программы и отсортированные
коды. Ключ считается **на лету** из полей направления, колонки в базе нет: деплой не пересобирает
базу (`olymp-ingest --if-empty`), и колонку было бы нечем заполнить. Уникальность на настоящей
сборке проверяет тест (659 направлений, 39 вузов — совпадений нет).

Таблица не входит в `DATA_TABLES` и **не ссылается внешними ключами на таблицы сборки**: иначе
`TRUNCATE … CASCADE` при пересборке молча очистил бы и её (тест это проверяет).

| Метод | Путь | Запрос | Ответ |
|---|---|---|---|
| POST | `/v1/shares` | `{kind: "program", program_id, benefit_type?}` · `{kind: "olympiad", olympiad_id, profile_id?, university_id?, benefit_type?}` · `{kind: "diplomas", diplomas: [spec…], benefit_type?}` | `201 {token, web_path, max_url}`; тот же экран — `200` и тот же токен |
| GET | `/v1/shares/{token}` | — | `200 {kind, benefit_type, found, resolved}`; `resolved` — актуальные id (`program_id`, `olympiad`, `profile_id`, `university`) и дипломы; `404` — нет токена или ссылка устарела |

- Клиент присылает id текущей сборки, сервер сам переводит их в ключи и проверяет по базе.
  Названия дипломов в снимок кладёт сервер — текст от клиента получатель не видит.
- POST идемпотентен по `payload_hash` (`INSERT … ON CONFLICT (payload_hash) DO UPDATE`), срок
  жизни продлевается; устаревшие ссылки удаляются при создании новых.
- Лимиты на создание (настройки `OLYMP_SHARE_*`): 60 в минуту с адреса и 20 000 за сутки, 429 с
  `Retry-After`. Минутный лимит выше, чем 30 в первом варианте ТЗ: ссылка создаётся заранее.
- GET не кэшируется: он увеличивает `opened_count`.
- Модуль API `modules/sharing` (контракт независимости в `pyproject.toml`).

## Безопасность и персональные данные
- В снимке нет id пользователя MAX и имени; дипломы — без привязки к человеку.
- Токен непредсказуем (10 символов base62 из `secrets`, ≈ 59 бит); создание ограничено лимитом.
- Ссылки живут 90 дней с последнего «Поделиться» этого экрана.
- Страница `/s/<token>`: `noindex` и `Referrer-Policy: no-referrer`.

## Критерии приёмки
- [x] На карточке направления, выдаче по олимпиаде и итогах дипломов есть «Поделиться».
- [ ] В MAX открывается выбор чата; получатель по кнопке в сообщении попадает на тот же экран —
      проверено «как из MAX» (`just max-link --start s_<token>`); в самом MAX — когда к боту
      привяжут адрес мини-приложения.
- [x] В браузере работает `navigator.share` или копирование ссылки; ссылка открывает тот же экран.
- [x] После пересборки старые ссылки открывают те же объекты (тест: пересборка с другими id).
- [x] Итоги дипломов у получателя — только чтение, его собственные дипломы не меняются.
- [x] Несуществующий токен → тост «Ссылка устарела», без ошибок JavaScript.
- [x] `startapp=diplomas|program-<id>|olympiad-<id>` по-прежнему работают.

## Решения по итогам ревью (2026-11-07)
- Идемпотентность — колонка `payload_hash`; токен — base62 (не base64url).
- Ключ направления включает профиль программы и squash полного названия вуза (не `short_name`).
- Маршрут `app/s/[token]/page.tsx` рендерит `OlympApp` с токеном; картинки — абсолютными путями.
- Снимок только по токену: ключи дипломов с кириллицей в `startapp` не помещаются.
- Счётчик открытий пишется в GET, поэтому GET не кэшируется.
