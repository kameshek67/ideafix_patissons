# F-07. ИИ-парсеры документов вузов

- Приоритет: P1 (сверщик — к демо), остальное — по готовности
- Статус: в работе — сверщик строк (T-087)
- Дата: 2026-11-08
- Связано: [ADR 0002](../adr/0002-data-from-xlsx.md) (данные из XLSX), [ADR 0010](../adr/0010-llm-gateway.md)
  (шлюз LLM), T-066, T-067, архивный конвейер `archive/olymp-rebuild` (`docs/plan/vision.md`)

## Зачем

Данные о льготах собраны в XLSX полуручным разбором документов вузов, и в них есть ошибки (ИТМО
01.03.02 — T-067). Жюри и родители спросят: «Почему вашим данным можно верить?» Проверять 25 тысяч
строк руками невозможно, а модель, которая сама пишет в базу, может выдумать льготу. Неверная льгота
может стоить школьнику поступления.

## Принципы для всех парсеров

1. **Модель предлагает, код проверяет, человек решает.** Модель не пишет в базу и не публикует данные.
2. **Запуск вручную, результат — файл.** Парсер запускается командой, а результат пишет в файл
   (CSV или JSON), который проходит ревью в PR. Сборка базы остаётся без LLM и воспроизводимой, CI
   модель не вызывает.
3. **Цитата и страница обязательны, их проверяет код.** Если код не нашёл цитату на указанной
   странице, результат не засчитывается. Самооценку модели не используем.
4. **Строгая схема ответа.** Модель возвращает только JSON, который проверяет код. Инструментов у неё
   нет, текст документа — недоверенные данные.
5. **Происхождение записано.** У каждого результата есть модель, версия промпта, адрес и хэш документа.
6. **Скачанное кэшируется.** Документ и его текст скачиваются и разбираются один раз, повторный
   запуск не тратит сеть.
7. **«Не знаю» лучше догадки.** Не нашёл документ, страницу или цитату — так и пишем.

Персональных данных в документах вузов нет, поэтому ограничений на провайдера, как в чате (F-02), здесь нет.

## Сверщик строк (T-087)

### Поведение

```
olymp-ai-verify --sample 100 --seed 2026 --out ai-verify.csv
olymp-ai-verify --university итмо --limit 20
olymp-ai-verify --sample 30 --dry-run      # без модели: какие страницы нашлись
```

Для каждой выбранной строки льготы:

1. **Описание строки.** Из базы берутся вуз, направление (код, название), тип льготы, олимпиады
   (сокращение, полное название, варианты написания), профиль, уровень, степень диплома, класс,
   предмет и порог ЕГЭ.
2. **Документы.** Кандидаты по порядку: ссылка строки, ссылка направления и файлы вуза из
   `university_documents` (не больше 8). Каждый документ скачивается, тип определяется по
   содержимому (`%PDF` или HTML), а не по заголовку сервера.
3. **Страницы.** Текст берётся постранично (PDF — `pdfplumber`, HTML — одна страница). Таблицы PDF
   раскладываются по строкам: объединённые ячейки заполняются значением сверху, в начале строки —
   код направления из заголовка раздела, заголовок колонок переносится на следующие страницы. Код выбирает
   до трёх страниц, где упомянута олимпиада строки (по варианту написания из `olympiad_aliases`),
   и повышает в рейтинге страницы, где встречаются код направления и профиль. Если олимпиада нигде
   не упомянута, модель не вызывается: статус `no_mention`.
4. **Модель.** Получает описание строки и выбранные страницы с номерами и отвечает JSON-ом:
   `verdict` (`confirmed`, `contradicted`, `not_found`), `page`, дословная `quote`, `mismatches`
   (поле и что сказано в документе) и `comment`. Ответ не по схеме — один повтор, затем `unverified`.
5. **Проверка кодом.** Цитата нормализуется (регистр, ё, кавычки, тире, переносы, пробелы) и ищется
   в тексте указанной страницы. Не нашлась — `unverified`. Цитата должна упоминать олимпиаду строки и
   содержать что-то кроме её названия, иначе тоже `unverified`: заголовок документа или голое
   название олимпиады ничего не доказывают. `confirmed` с непустыми `mismatches`
   становится `contradicted`. Поля в `mismatches` — только из списка.

### Статусы

| Статус | Значение | Что делать человеку |
|---|---|---|
| `confirmed` | документ подтверждает строку, цитата проверена кодом | выборочно перепроверить |
| `contradicted` | документ говорит иначе, цитата проверена | проверить и исправить данные (с тестом) |
| `not_found` | модель не нашла подтверждения на выбранных страницах | проверить вручную |
| `unverified` | цитата не найдена на странице или ответ не по схеме | проверить вручную |
| `no_mention` | олимпиада не упомянута ни в одном документе | проверить ссылку на документ |
| `no_document` | ни один документ не скачался или формат не поддерживается | проверить ссылку |
| `error` | сбой провайдера | перезапустить |

### Отчёт

CSV в UTF-8 с BOM (открывается в Excel): вуз, код и название направления, тип льготы, олимпиады,
профиль, уровень, степень, класс, предмет и порог ЕГЭ, статус, документ, страница, цитата,
расхождения, комментарий, модель, версия промпта, дата. Значения, начинающиеся с `= + - @`,
экранируются, чтобы Excel не принял их за формулу. В конце печатается сводка по статусам.

### Настройки и бюджет

- `OLYMP_LLM_BASE_URL`, `OLYMP_LLM_API_KEY`, `OLYMP_LLM_MODEL` — те же, что у чата.
  `OLYMP_PARSER_MODEL` задаёт отдельную модель для парсеров.
- `--max-requests` (по умолчанию 200) останавливает прогон до исчерпания лимита провайдера;
  `--pause` — пауза между запросами. Запросы идут последовательно.
- Температура 0. Текст страниц на запрос — не больше 12 000 символов.
- Кэш: `.cache/olymp/documents` (в `.gitignore`).
- Выборка: `--sample N --seed S` — случайная, но воспроизводимая при тех же данных; `--layer`
  (по умолчанию `detailed`, строки `derived` — вывод из правила, а не цитата).

### Сеть

- Скачиваются только `http(s)`, с таймаутом 30 с и ограничением 25 МБ на файл.
- Честный User-Agent, без обхода защиты от ботов.
- Проверка TLS по умолчанию включена. Часть сайтов вузов не проходит её из-за российских корневых
  сертификатов: такой документ получает `no_document`, а включить скачивание без проверки можно
  только явным флагом `--insecure`.

### Архитектура

- `packages/llm` (`olymp_llm`) — шлюз LLM, вынесенный из `olymp_api/llm`, чтобы им пользовались и
  API, и воркеры. `olymp_api.llm` остаётся как обёртка с прежними импортами.
- `packages/domain` (`olymp_domain.verify`) — чистая логика: нормализация цитаты, выбор страниц,
  разбор и сверка ответа модели.
- `apps/workers` (`olymp_workers.ai`) — скачивание и кэш документов, текст страниц, промпт, CLI.

## Первые результаты (2026-11-08, без модели)

Выборка 25 строк (`--seed 2026`), настоящие документы. У 15 строк олимпиада не упомянута ни в
одном доступном документе (`no_mention`). Это не ошибка поиска: у РЭУ, КФУ, Финансового
университета, Губкина в базе ссылки на страницу «Абитуриенту» или общие правила приёма, а таблицы с
олимпиадами среди них нет, часть ссылок отвечает 404. Значит, первая находка сверщика — у трети
строк нет ссылки на настоящий первоисточник. У остальных 10 строк страницы найдены (ВШЭ, МИФИ, МГУ).

## Прогон на настоящей модели (2026-11-08, `deepseek-v4.1-flash`)

Та же выборка из 25 строк, 10 запросов к модели, около минуты на запрос.

|---|---:|---:|

В v1 таблицы ВШЭ извлекались с перемешанными колонками («Прикладная 6 математика …»): модель
понимала строку верно, но собирала цитату из кусков, и код её не засчитывал. В v2 таблицы читаются
по ячейкам (`olymp_workers.ai.tables`): объединённые ячейки заполняются значением сверху, а в начале
строки стоит код направления из заголовка раздела. Модель цитирует строку целиком, код её находит.

Похоже на настоящие расхождения (их должен проверить человек): МИФИ 38.03.05 — у Московской
олимпиады по истории в документе уровень I, в базе II; МИФИ (филиалы) 08.03.01 — «Шаг в будущее»
указан только для физики, информатики и инженерного дела, в базе — математика.

## Качество

- **Эталон (T-088).** Человек размечает 50 строк по документам: верно или нет, и что именно не так.
  Тот, кто пишет парсер, эталон не создаёт.
- **Метрики сверщика на эталоне:** доля верных вердиктов (цель от 90%), доля ложных `confirmed` при
  ошибочной строке (цель 0) и доля проверенных цитат.
- **Пока эталона нет,** результат сверщика — подсказка для человека, а не отметка в интерфейсе.
