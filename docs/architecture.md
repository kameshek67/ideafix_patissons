# Как устроен Олимп

Документ для тех, кто читает код впервые. Запуск и выкатка — в [operations.md](operations.md),
планы — в [plan.md](plan.md).

## Путь данных

```
 источники         страницы приёмных комиссий, перечень РСОШ (rsr-olymp.ru), исходный XLSX
     │
 обход             olymp-refresh-sources: находит PDF, xlsx, HTML; пишет data/university_documents.json
     │
 извлечение        olymp-extract: документ → записи в общем JSON, у записи цитата и страница
     │
 проверка          код проверяет схему и то, что цитата есть на странице; olymp-eval-extract меряет по эталону
     │
 приёмка           человек смотрит файл и принимает его в data/extracted/
     │
 сборка базы       olymp-ingest: XLSX + справочники из data/ → PostgreSQL одной транзакцией
     │
 выдача            API → сайт, мини-приложение MAX, бот, помощник
     │
 жалоба            «не совпадает с документом» → очередь оператора → правка → снова сборка
```

Сейчас базу собирает `olymp-ingest` из `data/Olimpiady_BVI_100ballov.xlsx`. Файлы из
`data/extracted/` — результат `olymp-extract` по десяти документам эталона; в сборку базы они
пока не входят. Что из этого путь «документ → база» и чего в нём ещё нет, — в разделе про разбор
новых документов в [operations.md](operations.md).

## Слои данных

Таблица `benefits` хранит льготы направления. Поле `layer` говорит, откуда строка.

| Слой | Что это | В выдаче |
|---|---|---|
| `detailed` | строка «олимпиада × профиль» из подробного листа XLSX или разобранная из перечисления | да |
| `derived` | строка, выведенная из правила «любая олимпиада перечня по профилю X» | да |
| `summary` | текстовое правило без названий олимпиад; показывается в примечаниях | да |
| `raw` | исходное перечисление, уже разложенное на строки; нужно для трассировки | нет |

Рядом лежат данные, которые не относятся к строкам вузов:

- Перечень РСОШ на 2026/27: `data/rsosh_2026_27.json`, обновляется `just rsosh` раз в сезон.
  Из него у олимпиады появляется признак «в перечне» (`in_rsosh_2026_27`), у профиля — уровень
  по новому перечню (`level_2026_27`). Сборка базы сеть не использует.
- Правила приёма по закону: `data/admission_rules.json`. У каждого пункта есть дословная цитата,
  источник и дата проверки. Помощник отвечает по нему на вопросы о БВИ и сроках действия диплома.
  Поправки о призёрах, принятые Госдумой 25.11.2026 (по сообщению pnp.ru), записаны там же;
  подписание закона не проверено, поэтому сайт показывает их как проект («Правила 2027 (проект)»).
- Баллы за индивидуальные достижения: `data/individual_achievements.csv` и
  `data/individual_achievement_limits.csv`. Загружает `olymp-extra-points`.
- Сколько олимпиадников принимают вузы: `data/monitoring/olympiad_intake.csv` (по вузам базы; из
  сводной панели «Мониторинг эффективности вузов» его строит `olymp-analysis --monitoring`),
  связка с панелью — `data/monitoring/universities.csv`. Загружает `olymp-ingest` в `university_intake`,
  API отдаёт строку последнего года в карточке и списке вуза (`intake`).
- Карточки олимпиад: `data/olympiad_cards.json`; черновики для них делает `olymp-ai-cards`.

Таблицы пользователей и жалоб (`max_users`, `user_diplomas`, `user_ege_scores`, `share_links`,
`data_reports`) сборка не трогает: `olymp-ingest` очищает только таблицы сборки (`DATA_TABLES`
в `backend/db/src/olymp_db/models.py`).

## Бэкенд

Шесть пакетов в одном uv workspace. Правила импортов проверяет `lint-imports`: домен и шлюз LLM ни от чего не зависят, модули API не лезут друг в друга, помощник стоит выше поиска.

`backend/domain` — логика без базы и сети: разбор условий диплома и ЕГЭ (`diplomas.py`, `ege.py`),
нормализация названий (`textutils.py`), формат извлечённых записей (`extraction.py`), справочник
правил (`admission_rules.py`), баллы за достижения, скрытие персональных данных (`pii.py`).
Год кампании данных (`CAMPAIGN_YEAR = 2026`) и год поступления ученика (`ADMISSION_YEAR = 2027`)
заданы в `diplomas.py`.

`backend/db` — модели SQLAlchemy и миграции Alembic. Схема меняется только миграциями; у Alembic
должна быть одна голова.

`backend/llm` — шлюз к моделям с OpenAI-совместимым API.

`backend/api` — FastAPI, пути начинаются с `/v1`. Служебные: `/healthz`, `/readyz`, `/metrics`.
Модули в `olymp_api/modules`:

| Модуль | Что делает |
|---|---|
| `catalog` | вузы, направления, олимпиады, регионы, `/stats` |
| `search` | поиск вузов по олимпиаде и олимпиад по направлению |
| `achievements` | «Мои дипломы»: подбор льгот по дипломам, этап ВсОШ, правила 2027 |
| `sharing` | ссылка «Поделиться» на результат |
| `extra_points` | баллы за достижения по вузу |
| `reports` | приём жалоб: на карточку, на олимпиаду, на строку льготы |
| `assistant` | чат помощника, проверка ответа по базе |

Вход из MAX проверяется по подписи данных запуска (`max_auth.py`). Лимиты запросов и кэш используют
Redis, без него работают в памяти процесса.

Помощник собирает ответ из инструментов, которые читают базу (`tools.py`). Затем `factcheck.py`
проверяет названия и числа, а `claims.py` — утверждения о льготах по строкам базы: «кому»,
тип льготы, порог ЕГЭ, олимпиада вне перечня вуза. Метрики качества — `just assistant-eval`.

`backend/workers` — консольные команды и фоновые задачи. Все описаны в `justfile`.

| Модуль | Команда | Что делает |
|---|---|---|
| `ingest` | `olymp-ingest` | собирает базу из XLSX и справочников; `--if-stale` пропускает сборку, если ничего не изменилось |
| `extract` | `olymp-extract` | льготы из таблиц PDF и xlsx в общий JSON кодом, без модели |
| `eval_extract` | `olymp-eval-extract` | точность и полнота извлечения по эталону |
| `refresh_sources` | `olymp-refresh-sources` | обход страниц приёмных комиссий, ссылки на документы |
| `rsosh` | `olymp-rsosh` | перечень РСОШ с rsr-olymp.ru в `data/rsosh_2026_27.json` |
| `snapshot` | `olymp-snapshot` | снимок видимой выдачи; `--check` сверяет с базой |
| `validate` | `olymp-validate` | проверки качества базы; `--check-links` проверяет ссылки по сети |
| `report_regressions` | `olymp-report-regressions` | исправленные жалобы как сценарии, которые не должны вернуться |
| `export_reports` | `olymp-export-reports` | жалобы в CSV |
| `ai.verify` | `olymp-ai-verify` | сверка строк с документами моделью; решает человек |
| `ai_cards` | `olymp-ai-cards` | черновики карточек олимпиад |
| `max_bot`, `max_operator` | `olymp-max-bot` | бот MAX: приветствие и режим оператора |
| `tasks` | `dramatiq olymp_workers.tasks` | очередь: обход сайтов и пересборка базы |

### Внешние ассистенты (MCP)

`backend/mcp` — сервер `olymp-mcp`: пять инструментов читают только публичное HTTP API, доступа к базе и внутренним модулям нет. Адрес API задаёт `OLYMP_API_URL` (по умолчанию `https://ideafix.patissons.tech/api`), общение идёт через stdio — пример конфига MCP-клиента:

```json
{
  "mcpServers": {
    "olymp": { "command": "olymp-mcp", "env": { "OLYMP_API_URL": "https://ideafix.patissons.tech/api" } }
  }
}
```

## Фронтенд

Next.js 16, React 19, TanStack Query. Клиент API генерируется из `docs/openapi.json` в
`frontend/src/api`. Запросы к `/api/v1/*` сайт проксирует на API (`OLYMP_API_URL`).

Один экран с четырьмя вкладками (`OlympApp.tsx`):

- «Вуз» — вуз, направление, таблица олимпиад и условий;
- «Олимпиада» — поиск по названию и профилю, список вузов;
- «Мои дипломы» — форма диплома, итог по вузам и направлениям, переключатель правил 2027;
- «Баллы» — достижения по выбранному вузу.

Отдельно: страница общего результата `/s/[token]`, чат помощника (через `/api/assistant/chat`),
форма жалобы у строки льготы, окно «О сервисе», онбординг. Внутри MAX приложение читает данные
запуска через MAX Bridge (`MaxProvider.tsx`).

## Стабильный ключ строки

Порядковый `id` льготы меняется при каждой пересборке. Поэтому у строки есть `row_key`: 12 символов
SHA-256 от смысловых полей. В него входят вуз, направление, тип льготы, слой, олимпиады, профиль,
уровень, «кому», класс, предмет и порог ЕГЭ, источник (`workers/row_keys.py`). Если две строки
совпали, к ключу добавляется суффикс. На ключе держатся жалобы, снимок выдачи и регрессии.

## Снимок выдачи и проверки в CI

`data/snapshot/benefits.tsv` — отсортированная выдача: строка на пару «льгота × олимпиада» с
`row_key`. Правка разбора меняет файл, и `git diff` показывает, какие строки появились, пропали
или изменились. `just data-diff` сверяет базу со снимком, `just snapshot` обновляет его после
осознанной правки.

CI (`.github/workflows/ci.yml`) на каждый пуш и PR:

- backend: ruff, mypy, import-linter, одна голова Alembic, `alembic check`, pytest с настоящей базой;
- сборка базы, `olymp-snapshot --check` и `olymp-validate`;
- `docs/openapi.json` и `frontend/src/api/schema.d.ts` совпадают с кодом;
- frontend: lint, тесты, сборка;
- Docker-образы собираются, API отвечает на `/healthz`;
- gitleaks ищет секреты.

## Жалобы

Жалоба хранится в `data_reports`. Поля: вид (`program`, `olympiad`, `benefit`), для строки льготы —
`row_key` и причина, источник (`user`, `verifier`, `monitor`), статус. Статусы: `new`, `seen`,
`checking`, `fixed`, `correct`, `duplicate`. Статус `correct` («данные верны») база принимает только
вместе с цитатой из документа. Исправленные жалобы выгружаются в `data/regressions/reports.json`;
`olymp-report-regressions check` убеждается, что исправленная строка не вернулась в выдачу.

## Эталон и извлечение

- `data/eval/extraction/` — размеченные документы (десять вузов) с цитатами и схема `schema.json`.
- `data/eval/holdout/` — отложенные разметки тех же документов.
- `data/extracted/` — результат `olymp-extract`.
- `baseline-extract.json` и `baseline-xlsx.json` — метрики кода и старого XLSX для сравнения.

Запись совпала с эталоном, если совпали вуз, код направления, олимпиада, профиль и тип льготы.
