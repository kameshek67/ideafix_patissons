# 0001. Модульный монолит API и отдельные воркеры

- Статус: принято
- Дата: 2026-11-07 (впервые предложено 2026-11-05 в перестройке)

## Контекст
Запросы пользователей занимают миллисекунды, сборка базы и обход сайтов — минуты. Данные
вузов, олимпиад и льгот сильно связаны. Команда из четырёх человек, срок — хакатон.

## Решение
- API — один сервис FastAPI с модулями `catalog`, `search`, `achievements`. Модули не
  импортируют друг друга (import-linter).
- Долгие операции (сборка, обход сайтов, бот) — отдельные процессы в `apps/workers`
  (CLI и акторы Dramatiq поверх RabbitMQ).
- Логика без ввода-вывода — в `packages/domain`, модели и миграции — в `packages/db`.

## Альтернативы
Микросервисы по сущностям: сетевые вызовы на каждый запрос, распределённые транзакции и
лишняя инфраструктура без выгоды для четырёх человек.

## Последствия
Новая фича — новый модуль `modules/<имя>` со своими router/schemas/service и строкой в
контракте независимости. Общий код — в `olymp_api/*.py` или `packages/domain`.

## Когда пересмотреть
Если у ИИ-помощника появится отдельная нагрузка или хранение данных классов потребует
отдельной защиты — вынести их в отдельный сервис.
