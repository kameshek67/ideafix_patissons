# Архитектурные решения (ADR)

Решение записывается, когда его трудно отменить или когда новый участник может
«исправить» код, не зная причины. Шаблон — [0000-template.md](0000-template.md). Номер —
следующий свободный. Принятые ADR не переписываются: новое решение заменяет старое.

| № | Решение | Статус |
|---|---|---|
| [0001](0001-modular-monolith.md) | Модульный монолит API и отдельные воркеры | принято |
| [0002](0002-data-from-xlsx.md) | Данные собираются из XLSX в PostgreSQL одной транзакцией | принято |
| [0003](0003-stack-and-monorepo.md) | Стек и монорепозиторий uv + npm workspaces | принято |
| [0004](0004-openapi-contract.md) | OpenAPI — источник контракта, клиент генерируется | принято |
| [0005](0005-ui-parity-with-prototype.md) | Интерфейс повторяет прототип, Tailwind 3.4.16 | принято |
| [0006](0006-max-auth-initdata.md) | Мини-приложение MAX: вход по initData, данные на сервере | принято |
| [0007](0007-diploma-keys.md) | Дипломы и ссылки хранятся стабильными ключами, а не id | принято |
| [0008](0008-git-flow.md) | Ветки main + dev, squash, Conventional Commits | принято |
| [0009](0009-tasks-in-repo.md) | Задачи и ТЗ — Markdown в репозитории | принято |
| [0010](0010-llm-gateway.md) | Шлюз LLM, независимый от провайдера | предложено |

Решения несостоявшейся перестройки (правила и выпуски данных, четыре схемы БД и роли) лежат
в теге `archive/olymp-rebuild` (`docs/adr/0002`, `0003` там). К ним вернёмся после хакатона.
