# 0010. Шлюз LLM, независимый от провайдера

- Статус: принято (конкретная модель — по итогам T-020)
- Дата: 2026-11-07

## Контекст
ИИ-чат ([F-02](../specs/F-02-ai-chat.md)) должен отвечать о льготах. Бюджета на платные модели
нет: планируем бесплатные модели OpenRouter или локальную модель. Пользователи — школьники,
часть из них несовершеннолетние; мини-приложение работает в MAX.

## Решение
- Один модуль-шлюз `olymp_api/llm` с OpenAI-совместимым интерфейсом (`chat.completions` + tools).
  Провайдер выбирается настройками `OLYMP_LLM_BASE_URL`, `OLYMP_LLM_MODEL`, `OLYMP_LLM_API_KEY`.
  Подходят OpenRouter, Ollama, vLLM, LM Studio, а также GigaChat и YandexGPT через совместимые прокси.
- О льготах модель отвечает **только** через инструменты поиска по нашей базе (tool calling);
  у каждого факта — ссылка на строку и источник.
- В LLM не уходят персональные данные: ни id и имя пользователя MAX, ни чужие данные.
- Ответы модели и результаты инструментов — недоверенные данные; инструменты только читают.
- Таймауты, лимит токенов на запрос, лимит запросов на пользователя; поддельный провайдер для тестов.

- Провайдер на старте — бесплатные модели OpenRouter: решение владельца задачи от 2026-11-07. С ним
  запросы идут с `provider.data_collection: "deny"`, а текст проходит маскирование персональных данных.
- Модуль `assistant` — верхний слой над `search`, `catalog`, `achievements` (контракт `layers`). Те
  остаются независимыми. Так инструменты не дублируют SQL и не идут в API по сети.

## Альтернативы
Прямой SDK одного провайдера — привязка к нему и переписывание при смене модели.

## Последствия
Модель должна поддерживать tool calling. У бесплатных моделей нестабильные лимиты, поэтому
нужен резервный провайдер в настройках и понятное сообщение «помощник недоступен».

## Когда пересмотреть
Когда выберем провайдера и оценим качество на наборе вопросов из F-02.

## Дополнение 2026-11-08
Провайдер стенда — OpenAI-совместимый `https://ai.starimg.ru/v1`, модель `deepseek-v4.1-flash`
(решение команды, ключ — только в `.env` на сервере). Шлюз менять не пришлось: переменные те же
(`OLYMP_LLM_*`). Проверено на настоящих запросах: поток, вызов инструментов, ответы по-русски
по базе; первый фрагмент ответа приходит через 4–20 с. `provider.data_collection: "deny"` — параметр
OpenRouter, шлюз добавляет его только для `openrouter.ai`; у нового провайдера остаётся маскирование
персональных данных, условия хранения запросов у него не проверены. Полный прогон набора оценки
(T-020) не делали.

## Дополнение 2026-11-08 (T-087)
Шлюз вынесен из `olymp_api/llm` в пакет `packages/llm` (`olymp_llm`): им пользуются и API, и
воркеры (ИИ-парсеры F-07). `olymp_api.llm` остался обёрткой с прежними импортами и `make_provider`
из `Settings`; воркеры берут настройки из окружения (`provider_from_env`). Парсерам нужна
температура 0, отдельную модель задаёт `OLYMP_PARSER_MODEL`.
