# 0010. Шлюз LLM, независимый от провайдера

- Статус: предложено (провайдер — открытый вопрос)
- Дата: 2026-11-07

## Контекст
ИИ-чат ([F-02](../specs/F-02-ai-chat.md)) должен отвечать о льготах. Бюджета на платные модели
нет: планируем бесплатные модели OpenRouter или локальную модель. Пользователи — школьники,
часть из них несовершеннолетние; мини-приложение работает в MAX.

## Решение
- Один модуль-шлюз `olymp_api/llm` с OpenAI-совместимым интерфейсом (`chat.completions` + tools).
  Провайдер выбирается настройками `OLYMP_LLM_BASE_URL`, `OLYMP_LLM_MODEL`, `OLYMP_LLM_API_KEY`.
  Подходят OpenRouter, Ollama, vLLM, LM Studio, а также GigaChat и YandexGPT через совместимые прокси.
- О льготах модель отвечает **только** через инструменты поиска по нашей базе (tool calling);
  у каждого факта — ссылка на строку и источник.
- В LLM не уходят персональные данные: ни id и имя пользователя MAX, ни чужие данные.
- Ответы модели и результаты инструментов — недоверенные данные; инструменты только читают.
- Таймауты, лимит токенов на запрос, лимит запросов на пользователя; поддельный провайдер для тестов.

## Альтернативы
Прямой SDK одного провайдера — привязка к нему и переписывание при смене модели.

## Последствия
Модель должна поддерживать tool calling. У бесплатных моделей нестабильные лимиты, поэтому
нужен резервный провайдер в настройках и понятное сообщение «помощник недоступен».

## Когда пересмотреть
Когда выберем провайдера и оценим качество на наборе вопросов из F-02.
