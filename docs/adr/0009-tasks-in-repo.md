# 0009. Задачи и ТЗ — Markdown в репозитории

- Статус: принято
- Дата: 2026-11-07

## Контекст
Команда из четырёх человек работает параллельно и часто офлайн. Контекст задачи должен лежать
рядом с кодом, без доступа к внешним трекерам, а жюри должно видеть процесс в репозитории.

## Решение
- Задача — файл `docs/tasks/T-NNN-slug.md` с YAML-шапкой (статус, владелец, ветка, PR,
  зависимости) и критериями приёмки. ТЗ фичи — `docs/specs/F-NN-slug.md`.
- Статус хранится только в файле задачи. Доска — вывод `just tasks`; он не коммитится, чтобы
  не было конфликтов слияния.
- «Замок» на задачу — draft PR с ID задачи, открытый сразу после взятия.
- `scripts/tasks.py check` в CI проверяет шапки и зависимости.

## Альтернативы
- GitHub Issues + Projects — удобно, но контекст задачи оторван от кода и не
  версионируется вместе с ним.
- Один общий файл-доска — постоянные конфликты при параллельной работе.

## Последствия
Пока задача в работе, её статус в `dev` отстаёт, поэтому о занятости говорят открытые PR.
Позже задачи можно зеркалировать в GitHub Issues скриптом.

## Когда пересмотреть
Если команда вырастет или задач станет больше ~100.
