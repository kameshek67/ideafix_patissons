# Задачи

Одна задача — один файл `T-NNN-коротко.md` в этой папке. Статус и владелец хранятся
**только** в шапке файла. Дорожная карта и порядок работ — [ROADMAP.md](ROADMAP.md).
Почему так, а не GitHub Issues — [ADR 0009](../adr/0009-tasks-in-repo.md).

## Команды

```bash
just tasks          # доска: в работе / на ревью / к работе / сделано (+ открытые PR, если есть gh)
just tasks-next     # что можно брать: todo, зависимости готовы, нет открытого PR
just tasks-check    # проверка шапок (то же делает CI)
uv run python scripts/tasks.py claim T-012 --owner <ник>
uv run python scripts/tasks.py status T-012 review --pr 41
```

Без uv: `python3 scripts/tasks.py …` (зависимостей нет).

## Шапка

```yaml
---
id: T-012                  # совпадает с началом имени файла
title: Кнопка «Поделиться»
status: todo               # todo | in-progress | review | blocked | done | dropped
priority: P0               # P0 — к демо, P1 — желательно, P2 — если успеем, P3 — после хакатона
area: web                  # api | web | workers | domain | db | infra | docs | data | design | product
estimate: M                # S — до полудня, M — день, L — 2–3 дня (L дробим, если можно)
spec: docs/specs/F-01-share.md
depends: [T-011]
owner: ""                  # ник на GitHub — кто отвечает
branch: ""
pr: ""
updated: 2026-11-07
---
```

## Жизненный цикл

```
todo ──claim──► in-progress ──PR ready──► review ──merge в dev──► done
  │                 │
  └──► blocked ◄────┘ (в журнале — чем заблокирована)        dropped — решили не делать
```

1. **Выбор.** `just tasks-next`. Сначала P0, затем те, что разблокируют другие.
2. **Взятие.** Ветка от свежего `dev` → `tasks.py claim` → коммит `chore(tasks): взять T-NNN` →
   push → **draft PR в `dev`** с `T-NNN:` в заголовке. С этого момента задача занята: `just tasks`
   и `tasks-next` видят открытый PR, даже если файл в `dev` ещё говорит `todo`.
3. **Работа.** Журнал в конце файла задачи: что сделано, решения, вопросы. Это контекст для
   того, кому задачу передадут.
4. **Ревью.** `tasks.py status T-NNN review --pr N`, PR → ready for review.
5. **Готово.** При squash-слиянии статус в файле должен быть `done` (меняем последним коммитом
   ветки перед слиянием или ревьюер — при слиянии).

Нельзя: брать задачу с открытым PR другого человека; держать больше двух задач `in-progress`
на человека; менять чужую задачу без договорённости.
