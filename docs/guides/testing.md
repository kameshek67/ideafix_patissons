# Тесты

## Пирамида

| Уровень | Где | Инструмент | Что проверяем | Скорость |
|---|---|---|---|---|
| Unit (домен) | `packages/domain/tests` | pytest | разбор условий дипломов, нормализация названий — **на реальных формулировках из XLSX** | мс |
| Unit (web) | `apps/web/src/lib/*.test.ts` | vitest | форматирование, таблицы, дипломы, ссылки | мс |
| Компоненты | `apps/web/src/components/*.test.tsx` | vitest + Testing Library | экраны с замоканным `@/lib/api` | сотни мс |
| Схема БД | `packages/db/tests` | pytest + PostgreSQL | миграции создают все таблицы, сортировка `"C"`, ограничения CHECK | секунды |
| Сборка данных | `apps/workers/tests` | pytest + PostgreSQL | итоговые числа сборки из настоящего XLSX | ~1 мин (один раз за прогон) |
| API | `apps/api/tests` | pytest + httpx ASGI + собранная база | эндпоинты, условия вузов, вход MAX | секунды |
| E2E | `apps/web/e2e` (T-003) | Playwright | три сценария на телефоне и десктопе | минуты |

## Запуск

```bash
just up                         # PostgreSQL для тестов с базой
just test                       # всё
uv run pytest packages/domain   # только домен (без базы)
uv run pytest apps/api -k diploma -x
npm test --workspace olymp-web -- DiplomasTab
```

Тесты с базой создают **временную** базу на сервере `OLYMP_TEST_DATABASE_URL` и удаляют её в
конце; если сервер недоступен — пропускаются. Сборка из XLSX — один раз на прогон
(фикстура `built_database_url` в корневом `conftest.py`).

## Как писать

- **Тест — до или вместе с кодом**, в том же PR. Исправление бага начинается с теста, который
  его воспроизводит.
- **Реальные данные** важнее синтетики: формулировки условий берутся из таблиц вузов (см.
  `test_diplomas.py`). Так тест ловит то, что встретит пользователь.
- **Табличные тесты** (`pytest.mark.parametrize`) для разбора текста: вход → ожидание,
  по строке на случай.
- **Не мокай то, что можно поднять**: API тестируется на настоящей PostgreSQL. Сеть (сайты вузов,
  MAX, LLM) — всегда подделка (`FakeProvider`, поддельный API MAX в `test_max_bot.py`).
- **Компоненты**: ищи элементы по роли и тексту (`getByRole`, `getByText`), а не по классам.
- **Изменились итоговые числа сборки** — это изменение данных: объясни в PR, почему новые
  числа правильные.
- Нельзя: удалять или ослаблять тесты, чтобы CI позеленел; `skip` без ссылки на задачу.

## CI

`.github/workflows/ci.yml` на каждый PR и push в `dev`/`main`:

| Job | Что |
|---|---|
| `python` | ruff, format, mypy, import-linter, pytest с PostgreSQL, актуальность `docs/openapi.json` |
| `web` | `npm ci`, актуальность клиента API, tsc, vitest, `next build` |
| `tasks` | `scripts/tasks.py check` |
| `secrets` | gitleaks по всей истории |

Красный CI блокирует слияние. Если CI падает не из-за твоих изменений — сообщи в чате
команды и заведи задачу, не чини молча в чужой ветке.
