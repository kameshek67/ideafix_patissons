# Поступай по олимпиаде — БВИ и 100 баллов

Full-stack прототип для хакатона: двусторонний поиск льгот олимпиадников по данным
приёмных кампаний 2026 года (17 листов исходного XLSX).

* **Сценарий 1 — «Ищу олимпиады под ВУЗ»**: выбрал вуз → направление → видишь, какие олимпиады
  дают БВИ, какие — 100 баллов, и что нужно подтвердить ЕГЭ.
* **Сценарий 2 — «Куда поступить с моей олимпиадой»**: ввёл «Высшая проба» / «ВсОШ» / «пвг» →
  выбрал профиль олимпиады → получил **список вузов** → нажал на вуз → таблица его льгот.

Вся конкретика выводится **таблицами** (сортировка по колонке, фильтр по строке, выгрузка CSV).
Текстом остаются только общие правила вуза, в которых нет названий олимпиад, — они собраны
в свёрнутый блок «Общие правила и примечания».

```
Python 3.12 · pandas/openpyxl · SQLite + FTS5 · FastAPI · Tailwind + vanilla JS · Docker Compose
```

## Быстрый старт (Docker)

Нужен запущенный Docker Desktop (или демон docker на Linux). Из каталога проекта:

```bash
docker compose up --build -d
```

* приложение — http://localhost:8080
* Swagger-документация API — http://localhost:8000/docs

При первом запуске контейнер `backend` сам собирает базу из `data/Olimpiady_BVI_100ballov.xlsx`
(≈30 секунд, видно в `docker compose logs -f backend`) и кладёт её в volume `bvi-data`.
Volume переживает пересоздание контейнеров, так что дальше приложение стартует за секунды.

> База специально живёт в volume, а не на диске хоста: bind-mount папки Windows в WSL2
> замедляет SQLite примерно в 30 раз (запрос `/api/stats` — 3.5 с против 0.12 с).
> Сам XLSX при этом подключён с хоста только для чтения, поэтому заменить исходные данные
> можно без пересборки образа.

Управление:

```bash
docker compose ps           # статус контейнеров
docker compose logs -f      # логи
docker compose stop         # остановить
docker compose start        # снова запустить
docker compose down         # остановить и удалить контейнеры (volume с базой остаётся)
docker compose down -v      # удалить и базу тоже — соберётся заново при следующем старте
```

Пересобрать базу после замены `data/Olimpiady_BVI_100ballov.xlsx`:

```bash
docker compose exec backend python ingest_data.py
```

> Windows: если `docker` не находится, откройте новый терминал после установки Docker Desktop
> либо вызывайте `& "$env:LOCALAPPDATA\Programs\DockerDesktop\resources\bin\docker.exe"`.

## Запуск без Docker

```bash
cd backend
pip install -r requirements.txt
python ingest_data.py                       # создаст ../data/bvi_database.db
uvicorn main:app --reload --port 8000       # API + статика фронтенда
```

Открыть http://localhost:8000 — FastAPI отдаёт и API, и SPA (одноконтейнерный режим).
Вспомогательные скрипты: `run_local.ps1` (Windows) и `run_local.sh` (Linux/macOS).

## Что делает парсер (`ingest_data.py`)

1. **Лист «База»** (675 строк) → `universities` / `programs` / `benefits`
   (формулировка правила + примечание + ссылка на источник).
2. **13 подробных листов** → строки таблиц (`layer='detailed'`), у каждого листа свой адаптер:

   | Лист | Что извлекается |
   |---|---|
   | ВШЭ подробно / филиалы / ВсОШ | программа × олимпиада × профиль × льгота, порог ЕГЭ, класс |
   | РЭУ подробно | 27 510 строк агрегируются в 8 124 правила (годы и предметы ЕГЭ схлопнуты) |
   | МИФИ подробно | списки кодов направлений раскрываются построчно |
   | Бауманка подробно | 10 групп направлений; «БВИ только победителям» → призёрам отдельная запись на 100 баллов |
   | Финуниверситет | группы программ 1–8, уровни олимпиад по годам |
   | КФУ подробно | и «все направления с ВИ по предмету», и явные списки кодов |
   | УрФУ подробно + легенда | коды профилей РСОШ расшифровываются по листу-легенде |
   | ЦУ фаст-трек, Иннополис, Пирогова, УрФУ +4 балла | фаст-трек, особые права, ИД |
   | ВШЭ международные | 12 международных олимпиад → БВИ членам сборных РФ |

3. **Справочник олимпиад.** В исходнике ~450 вариантов написания одного и того же
   (артефакты извлечения из PDF: `Всероссийская о4л импиада`, `М2 осковская олимпиада ш8 кольников`,
   обрывки строк). Они схлопываются в **173 канонические олимпиады**:
   * `squash()` — ключ из одних букв (без цифр, кавычек, пробелов) устойчив к мусору;
   * `olympiad_seeds.py` — якоря («высшаяпроба», «покоривороб», «формулаединства», …) с
     исключениями, чтобы «Всероссийская олимпиада школьников **«Высшая проба»**» не попала в ВсОШ;
   * обрывки приклеиваются к полному названию по вхождению подстроки;
   * плюс пользовательские алиасы: `всош`, `оммо`, `пвг`, `мош`, `нто`, `вышка`, `мфти`.
4. **Профили олимпиад** (`olympiad_profiles`). Льгота даётся за пару «олимпиада + профиль»:
   у НТО это 42 профиля («искусственный интеллект», «интеллектуальные робототехнические
   системы», «инфохимия»…), у «Высшей пробы» — 34. Названия нормализуются
   (`автоматизация бизнес- процессов` → `автоматизация бизнес-процессов`, регистр, кавычки),
   а редкие обрывки строк из PDF приклеиваются к полному профилю по вхождению подстроки
   или длинному общему началу — 618 профилей после нормализации схлопнулись в 560.
5. **Разбор текстовых перечислений.** Сводные формулировки «Базы» вида
   `[143 вар.] «Высшая проба» (информатика, I ур.); «Ломоносов» (математика, I ур.); …`
   (до 10 000 символов в одной ячейке) раскладываются в такие же строки таблицы.
   `parse_enumeration()` понимает четыре формата источников:
   `Олимпиада (профиль, уровень)`, `Олимпиада: профиль (поб.+приз., 11 кл.)`,
   `Предмет: олимпиада, олимпиада` и `A, B, C — уровень I, 11 класс, победитель и призёр`.
   Названия проверяются по справочнику олимпиад — что не опознано, в таблицу не попадает.
   Результат: **+960 строк**, 859 текстов скрыто как дубли уже разобранных таблиц
   (`layer='raw'`), 477 общих правил без названий олимпиад остались текстом (`layer='summary'`)
   и показываются примечаниями.
6. **Правила «по профилю олимпиады».** Часть вузов не перечисляет олимпиады вовсе, а задаёт
   льготу профилем перечня: ИТМО — «любая олимпиада перечня I–III уровня по информатике и
   математике… все технологические профили (…, мобильные приложения, …) — БВИ»,
   УрФУ — «перечневые олимпиады I–III уровня по профилям: Астрономия, Анализ данных, …».
   `parse_profile_rules()` вытаскивает из такого текста профили, диапазон уровней и «кому»,
   а `ProfileIndex` сопоставляет написание вуза со справочником профилей — со склонениями
   («мобильные приложения» → «разработка мобильных приложений») и сокращениями
   (ИКТ, ИИ, финтех, промпрограммирование, космоснимки, аэрокосмос). Каждое правило
   разворачивается в конкретные пары «олимпиада + профиль» с уровнем этой пары по перечню.
   Результат: **+24 588 строк** (`layer='derived'`, в интерфейсе помечены бейджем «по профилю»).
   Правила про ВсОШ не разворачиваются — она и так прописана отдельными строками, а правила
   «перечневых» олимпиад не разворачиваются на ВсОШ/ЛНР/ДНР.
7. **Связи и индексы**: `benefit_olympiads` (65 080 связей «льгота ↔ олимпиада (+профиль)» — по
   колонке подробного листа, по тексту условий или по профилю), `benefit_keywords` (143 тыс.
   ключевых слов: уровень I/II/III, победитель/призёр, класс, порог ЕГЭ, предметы) и
   FTS5-индекс `search_index`.

Итог сборки: **39 вузов · 659 направлений · 54 950 строк таблиц (30 362 из документов +
24 588 выведенных из правил по профилю) + 477 текстовых правил · 173 олимпиады · 635 профилей**.

### Слои данных

| `layer` | что это | где видно |
|---|---|---|
| `detailed` | строка «олимпиада × профиль × уровень» из документа вуза | таблицы |
| `derived` | строка, выведенная из правила «любая олимпиада перечня по профилю X» | таблицы, бейдж «по профилю» |
| `summary` | правило вуза без названий олимпиад и профилей («уровень II — весь перечень») | блок примечаний |
| `raw` | исходное перечисление, уже разложенное в строки | только в БД, для трассировки |

### Как склеиваются «База» и подробные листы

Одно направление приходит из разных листов в разном виде: `№3. Прикладная математика и
информатика (01.03.02)` в «Базе» и `Прикладная математика и информатика` + код `01.03.02`
в «ВШЭ подробно». `ProgramRegistry` строит для программы несколько ключей (имя без кодов,
набор кодов, «Группа N», предмет ВИ в кавычках) и объединяет записи — поэтому в карточке
направления рядом лежат и сводное правило вуза, и подробный список олимпиад.

## API

| Метод | Назначение |
|---|---|
| `GET /api/health` | статус, путь к БД, доступность FTS5 |
| `GET /api/stats` | счётчики для дашборда, статистика по вузам, топ олимпиад, отчёт парсера |
| `GET /api/regions` | Москва / Санкт-Петербург / Регионы |
| `GET /api/universities?region=&q=` | вузы с числом направлений и льгот |
| `GET /api/programs?university_id=&q=` | направления вуза |
| `GET /api/olympiads?q=&featured=&limit=` | автокомплит по названиям и сокращениям (+ число профилей) |
| `GET /api/olympiads/{id}/profiles` | профили олимпиады со счётчиками БВИ / 100 баллов / вузов |
| `GET /api/search/by-program?program_id=` | строки таблиц по типам льгот (`groups[].rows`), примечания, список олимпиад |
| `GET /api/search/by-olympiad?q=&olympiad_id=&profile_id=&university_id=&region=&benefit_type=` | обратный поиск: список вузов, а с `university_id` — все строки выбранного вуза |

Примеры:

```bash
curl "http://localhost:8000/api/search/by-olympiad?q=высшая%20проба&region=Москва"
curl "http://localhost:8000/api/search/by-olympiad?q=НТО&profile_id=159&benefit_type=БВИ"
curl "http://localhost:8000/api/olympiads/$(curl -s 'http://localhost:8000/api/olympiads?q=нто' | python -c 'import json,sys;print(json.load(sys.stdin)["items"][0]["id"])')/profiles"
curl "http://localhost:8000/api/search/by-program?program_id=135"
```

`by-olympiad` возвращает точные итоги (`total_universities`, `total_programs`) отдельным
агрегатом, а подробные строки — с лимитом, поэтому счётчики не «плывут» на больших олимпиадах.

## Откуда берутся ссылки на документы

Прямая ссылка на PDF живёт один приёмный сезон (`…/2026/Lgoty.pdf`), а адрес раздела
«Документы / Олимпиады» у вуза меняется редко. Поэтому система устроена так:

1. **[university_pages.py](backend/university_pages.py)** — единственный файл, который
   поддерживается руками: вуз → стабильная страница раздела. Статусы: `verified`
   (обход нашёл документы), `page` (страница верная, но документы выводятся текстом
   или рендерятся скриптом), `guarded` (сайт закрыт от автоматических запросов, в браузере
   открывается), `todo` (адрес временный, нужен раздел с документами).
2. **[refresh_sources.py](backend/refresh_sources.py)** обходит эти страницы, находит на
   них файлы по ключевым словам («олимпиад», «особые права», «приложение», «правила приёма»)
   и складывает в таблицу `university_documents` + кэш `data/university_documents.json`:

   ```bash
   docker compose exec backend python refresh_sources.py            # обновить
   docker compose exec backend python refresh_sources.py --dry-run  # только посмотреть
   docker compose exec backend python refresh_sources.py --only кфу # один вуз
   ```

3. **Сборка базы** подхватывает кэш, поэтому обход сайтов нужен не после каждой пересборки,
   а раз в сезон. В карточке направления первой идёт кнопка «Документы приёмной комиссии»
   (страница), за ней — конкретные файлы, найденные на ней.

Чтобы добавить новый вуз, достаточно одной строки в `university_pages.py` — дальше всё
сделает `refresh_sources.py`.

## Проверка качества данных

Данные собраны автоматически из документов приёмных комиссий, поэтому в комплекте
идёт валидатор — его стоит запускать после каждой пересборки базы:

```bash
docker compose exec backend python validate_data.py
```

С флагом `--check-links` он дополнительно проверяет все ссылки на первоисточники
HTTP-запросом (две попытки, 403 от антибот-защиты не считается ошибкой):

```bash
docker compose exec backend python validate_data.py --check-links
```

Что проверяется: направления без ссылки на источник, «ссылки», которые на самом деле
текст, URL с пробелами, доля строк без опознанной олимпиады, полностью одинаковые
строки таблиц, подозрительно редкие олимпиады (обрывки строк из PDF), направления
без таблиц, доля строк, выведенных из правил «по профилю», вузы без страницы приёмной
комиссии, страницы со статусом `todo` и ссылки, которые не обновлялись больше полугода.
Код возврата 1, если есть ошибки уровня ERROR — годится для CI.

В интерфейсе у каждого направления есть кнопка **«Открыть документ вуза»** с названием
приложения к правилам приёма и подпись, что таблица собрана автоматически: любую строку
можно перепроверить в первоисточнике.

## Известные ограничения

* Строки со слоем `derived` — это **вывод из правила вуза**, а не цитата из его таблицы:
  «любая олимпиада перечня с профилем X» разворачивается по справочнику профилей, собранному
  из документов других вузов. Если вуз не включил какую-то олимпиаду в свой перечень или
  профиль назван иначе, чем в справочнике, строка может отсутствовать или быть лишней —
  поэтому такие строки помечены бейджем «по профилю» и всегда снабжены ссылкой на источник.
* Уровень пары «олимпиада + профиль» определяется по большинству упоминаний в подробных листах
  (498 пар); для пар без уровня фильтр по уровню в правиле не применяется.
* Олимпиады **ДАНО** нет в исходной таблице (её нет в перечне РСОШ), поиск по ней вернёт пусто.
* 477 правил сформулированы без названий олимпиад и без профилей («весь перечень уровня I»,
  условия грантового конкурса) — разложить их в таблицу нечем, они показываются в блоке
  примечаний; часть направлений описана только такими правилами и таблиц не имеет.
* **Филиалы НИЯУ МИФИ** в источнике идут одной строкой «Филиалы», без разбивки по городам,
  поэтому в колонке города стоит «филиалы в регионах» и примечание об этом. Города, которые
  можно определить по названию вуза (Казань, Екатеринбург, Красноярск, Новосибирск, Иннополис),
  проставлены в `universities.city`.
* У 12 388 связей (из 39 532) профиль не указан: это правила вузов, сформулированные общим
  текстом, и листы без колонки профиля (УрФУ, ВсОШ по предметам). В выдаче они попадают
  в «Все профили» и подписаны отдельной строкой под чипами.
* Данные справочные: в каждой карточке есть ссылка «Источник» на документ приёмной комиссии.
